# 日志管理工具能力说明

## 1. 文档目的

本文档从使用者和交付验收角度，梳理 SecurityTool 中“日志管理”工具当前已落地的能力、使用条件和明确边界。

- 页面路由：`log-manage`
- 主页面：`entry/src/main/ets/views/log-manage/overview/LogManagePage.ets`
- 设计基线：`docs/03-模块设计/日志管理组件设计说明.md`
- 文档结论基于 2026-08-13 仓库中的生产代码、模块设计和测试资产。

## 3. 日志采集能力

### 3.1 系统审计日志

工具通过 `@kit.DeviceSecurityKit.securityAudit` 订阅安全审计事件，并映射为可查询、可展示、可导出的本地日志。

| 日志类型 | 当前覆盖内容 |
| --- | --- |
| 文件操作日志 | 文件访问/拦截、KIA 文件事件，以及已验证的 `FILE_CREATE`、`FILE_CLOSE`、`FILE_COPY`、`FILE_SETOWNER`、`FILE_SETMODE`、`FILE_SETEXTATTR`、`FILE_DELETEEXTATTR` |
| 用户认证日志 | 账户及认证相关审计事件，保留认证类型、结果、调用方、发生时间等可用字段 |
| 权限变更日志 | 系统权限事件，展示权限名称、目标等结构化信息 |
| 崩溃审计日志 | 审计框架提供的崩溃相关事件 |
| 通用审计日志 | 剪贴板、截屏/录屏/投屏、移动存储、打印机、进程、摄像头、应用、EDM、证书、DNS、应用安装/卸载/更新/恢复/启动拦截、USB 访问拦截 |

文件审计会按当前前台用户的用户目录挂载 `FILE_PATH_PREFIX` 过滤器。无法获取用户上下文、系统不支持过滤器或过滤器挂载失败时，工具不会退化为无边界的文件事件订阅。

为避免工具自身操作制造日志噪音，新增文件事件入库前会过滤本应用设置、主题、HiAppEvent、应用数据库、导出目录和导入临时文件等内部噪音。

### 3.2 应用崩溃与冻结采集

工具通过 `hiAppEvent` 监听：

- `APP_CRASH`：应用崩溃。
- `APP_FREEZE`：应用冻结。

采集结果归类为“崩溃日志”，可包含进程名、PID、UID、事件名和异常摘要等信息。

### 3.3 设备开关机审计日志

- 通过 `securityAudit` 直接订阅真机安全审计配置中的 `DEVICE_POWER_ON (0x16000001)` 和 `DEVICE_POWER_OFF (0x16000002)`。
- 审计事件分别映射为 `device.power_on` 和 `device.power_off`，归类到“开关机日志”。
- 日志时间优先使用载荷中的 `happenTime`；安全审计服务重新订阅时回放的 sticky 事件由仓储唯一索引去重。
- 应用冷启动、企业管理员生命周期和公共事件均不生成或补偿开关机日志。

## 4. 日志查询与页面展示

### 4.1 统计信息

页面顶部展示四项统计：

- 总计：当前本地库全部日志数。
- 今日：当天新增日志数。
- 过滤后：当前筛选条件命中的总数。
- 当前显示：当前页实际展示的日志数。

### 4.2 筛选与搜索

- 按 8 种日志类型筛选，也可查看全部类型。
- 按全部时间、最近 1 小时、最近 12 小时、最近 24 小时或最近 3 天筛选。
- 关键字搜索覆盖日志摘要、进程名和文件路径，查询不区分大小写。
- 筛选条件同时影响列表、统计、分页和 CSV 导出结果。

### 4.3 分页与详情

- 每页可选 20、50 或 100 条。
- 支持上一页、下一页和输入页码跳转。
- 日志详情弹窗展示时间、事件类型、摘要、进程和事件专属的结构化字段。
- 文件操作会统一展示归一化文件路径；复制等同时存在旧路径和新路径的事件，会保留两者。
- 通用审计日志展示事件说明和原始 JSON；EDM 事件还会展示已验证的操作对象和中性中文备注。

### 4.4 自动刷新与异常保护

- 列表页处于活跃状态时，本地存储变更会触发页面刷新。
- 进入存储设置页时暂停列表活跃态和自动刷新，返回日志列表后再恢复。
- 查询或分页失败时保留最近一次成功列表，不将失败伪装成“0 条日志”。

## 5. 本地存储与留存策略

日志使用 `@ohos.data.relationalStore` 持久化到本地 RDB 表 `log_entries`，不依赖云端存储。

| 配置项 | 可选值 | 默认值 |
| --- | --- | --- |
| 最大本地条数 | 5000、10000、20000、50000、100000 | 20000 |
| 保留天数 | 7、14、30、90、180 天 | 30 天 |

维护规则：

- 按自然日计算保留截止时间，自动删除过期记录。
- 超过最大条数时，保留最新日志，裁剪旧日志。
- 修改存储配置并保存后会立即执行容量和保留期校准。
- 保存失败时保留“未保存”状态，允许重试；后续维护失败时尝试回滚配置。
- 支持经用户确认后清空全部本地日志。

## 6. 离线日志导入

### 6.1 入口与交互

用户通过“添加日志”选择 `.zip` 日志包。导入期间显示覆盖整个应用窗口的模态加载框，防止重复操作。处理完成后返回解压文件数、扫描数、解析数、新增数、重复跳过数、过期跳过数、丢弃数和失败数。

### 6.2 支持的日志包结构

- 支持外层 zip 和嵌套 zip，嵌套解压最大深度为 4。
- 支持 `hilog/hilog_kmsg*` 内核日志，包括 `.gz` 压缩文件。
- 支持 `faultlogger` 目录下的 `appfreeze-*`、`jscrash-*`、`cppcrash-*` `.log` 文件。
- 支持下列白名单系统日志：

| 日志范围 | 解析类别 |
| --- | --- |
| `eventlog/service_timeout_warning-*.log` | 服务超时异常 |
| `eventlog/window_exception_detection-*.log` | 窗口异常检测 |
| `hisi_logs/hisi_diaginfo.log` | 硬件/SoC 诊断 |
| `f2fs-tools/fsck.log` | 文件系统检查 |
| `f2fs-tools/resize.log` | 文件系统扩容/维护 |
| `memory/proc_meminfo*.txt` | 内存资源快照 |
| `memory/proc_memview*.txt` | 内存视图快照 |
| `memory_leak/*.txt` | 内存泄漏诊断 |
| `updater/updater_log` | 系统升级/恢复日志 |
| `updater/updater_stage_log` | 系统升级阶段日志 |
| `log/sys_installer.log` | 系统安装/参数更新日志 |
| `log/hsld.log` | 系统服务启动/挂载日志 |

### 6.3 内核日志识别范围

当前内核解析会提取以下高价值事件：

- 安全访问控制拒绝。
- Binder/IPC 权限失败。
- DEC 规则设置。
- DEC 设备文件事件。

普通 `remoteLog/hilog/hilog.*` 文本不在当前导入范围内。

### 6.4 性能、去重和清理

- zip 准备、文件枚举和单文件解析放到 TaskPool 执行，避免长时间占用 UI 主线程。
- 候选文件按文件串行解析，单文件结果每 1000 条分批入库，减少大日志包的内存和 TaskPool 序列化压力。
- 通过稳定日志 ID、批内去重和库内查重防止重复导入覆盖旧数据。
- 过期日志在入库前按当前保留策略跳过。
- 导入过程中约每累计 10000 条执行一次不刷新页面的容量维护，全部完成后再统一维护并刷新一次。
- 导入成功、失败或异常结束后，都会尝试清理应用私有目录中的 `log_import_tmp` 临时工作区。

## 7. CSV 导出

- 导出对象是“当前筛选条件”命中的全部日志，不仅是当前页。
- 导出字段包含：时间、事件类型、详情、进程名、PID。
- 每 500 条分页读取数据并追加到 CSV，避免一次性加载全部日志。
- CSV 使用 UTF-8 BOM、CRLF 换行和统一字段转义，便于在常用表格软件中打开中文内容。
- 通过系统 `DocumentViewPicker` 的 `DOWNLOAD` 模式由用户选择保存位置。
- 无可导出数据、用户取消或文件写入失败时，页面会给出对应反馈。

## 8. 权限、系统依赖与降级

### 8.1 关键系统依赖

| 系统能力 | 用途 |
| --- | --- |
| `@ohos.hiviewdfx.hiAppEvent` | 监听应用崩溃和冻结 |
| `@kit.DeviceSecurityKit.securityAudit` | 订阅文件、账户、权限、开关机及通用安全审计事件 |
| `@ohos.data.relationalStore` | 本地日志 RDB 存储 |
| `@kit.CoreFileKit` | zip 选择、CSV 保存和文件读写 |
| `@kit.ArkTS.taskpool` | 大日志包准备和解析后台任务 |

### 8.2 权限和部署要求

- 实时审计订阅需要 `ohos.permission.QUERY_AUDIT_EVENT`。
- 权限已同时声明在 `entry/src/main/module.json5` 和 `hapsigner/UnsgnedDebugProfileTemplate.json`。
- 若权限、签名 profile 或设备系统能力不满足，实时审计事件可能无法采集。

### 8.3 降级策略

- 审计客户端不可用、权限不足或单个事件订阅失败时，保留成功的其它采集源。
- 实时审计降级不影响查看已入库日志、离线导入、筛选、详情、导出和清理。
- 单个离线文件解析失败会计入失败统计，不影响其它候选文件继续处理。
- 导入批次入库或存储维护失败时停止后续处理；已成功入库的批次不回滚，重试时由去重机制保护。

## 9. 当前明确不具备的能力

下列内容不应在交付或演示时宣称为已实现：

- 没有远程日志上报、云端存储或云端审计平台。
- 没有定时导出、自动导出任务或导出任务调度。当前只支持用户手动导出。
- 没有用户自定义审计规则、告警规则或告警联动。
- 没有审计事件策略下发功能；日志管理负责采集和查看，不实现系统审计框架本身。
- 不导入普通 `remoteLog/hilog/hilog.*` 文本。
- 实时订阅不包含 `NETWORK_TRAFFIC` 和 `NETWORK_CONN`，以避免样机上的高频日志风暴。
- 当前无独立面向其它业务模块的日志 SDK 或公共跨模块写入接口。

## 10. 建议验收路径

1. 进入“日志管理”，确认四张统计卡、筛选栏、列表和顶部操作按钮可见。
2. 切换日志类型和时间范围，输入关键字，确认“过滤后”与列表、分页一致。
3. 打开一条日志详情，确认摘要和结构化字段正常。
4. 执行一次可观测的策略或系统操作，确认对应审计日志可在页面查到；若无数据，优先核对审计权限、签名 profile 和设备能力。
5. 选择合规 zip 日志包执行“添加日志”，核对导入统计和新增的内核/崩溃/系统日志。
6. 在有筛选条件时执行“导出日志”，确认 CSV 内容与筛选范围一致。
7. 修改最大条数或保留天数并保存，确认设置生效。
8. 最后执行“清空日志”，确认有二次确认且清空后统计与列表同步。
